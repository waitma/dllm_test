正式测量前另有一个实际 HF 完整窗口，独立 oracle 阶段暂停裁剪；该阶段额外有 1 次 optimizer 调用及 8 次 manual backward，不算入正式三个窗口。使用同一 768 条 dataset / sampler，避免独立 256 子集改变首窗抽样。模型初始化、首窗实际输入与正式阶段匹配。人工 corruption 和 log-softmax/gather CE 独立实现，逐微步恢复捕获的 RNG 并按 loss/GA 累积；逐参数比较梯度，同时核验全向量 dot/平方和导出的 scale 与相对 L2 误差。正式阶段在原 clip 函数执行前观察首窗梯度并与 oracle 比较；透明 observer 随后调用原 clip，不修改原 Trainer train/training_step、loss 结果或 attention。固定限界为 allclose rtol0.005/atol0.00002、scale 到 1 与相对 L2 均 ≤0.005，CE rtol/atol0.00002；不会失败后放宽。oracle 的 GPU 模型/optimizer 释放并实际 allocated=0 后，才重构正式 scratch 模型并 reset/read GPU peak。

真实 `trainer.evaluate()` 保留四档 mask，来源为 7 条短人工 mixed（padding、single/double target、relation present）及 17 条 full capacity stress（relation absent），eval batch16；每 mask 三个实际 batch，共 12 批/96 record evaluations。CPU oracle 不调用原 mask 代码，独立重新生成 hash mask、CE、AA/END/relation 正误、first-END/missing/length 四个原始 endpoint 字段，覆盖全部 16 个 totals，并独立核对 source macro/token micro/四 mask 均值/full-mask aliases 和 None。训练 AdamW state 在评估中保持驻留，满长 batch 的峰值包含它。callback 在 prediction、log、evaluate 中主动消耗 Python/NumPy/Torch CPU/CUDA RNG，评估前后完整状态 hash 必须相同。

原始 `gpu_release_raw.json` 只保存 selected logits/labels、全 target slot argmax、shape/dtype 和输入 hash，供只读 verifier 重算；不存完整 activation、梯度、model 或 checkpoint。summary 保持旧 `GPU_SCHEMA` / phases 合同，同时以 `proof_extension` 绑定 plan、full source before/after、HF/Accelerate/optimizer 来源、runtime manifest、producer、wrapper、fixture 和 raw bytes SHA。训练和评估分别须 ≤85% GPU 总显存；上限 oracle240/train720/eval240 秒、整体1200 秒；OOM 没有较小批次 fallback。producer 只写 raw、summary、`PRODUCER_SUCCESS.json`（candidate_ready）与进度；失败只保留分类 FAILED / 进度并撤销 SUCCESS。它不声明正常子进程退出/descendant cleanup，也绝不写 `GPU_RELEASE_COMPLETE.json`；root wrapper 完成这些实际观察和强验证后才有权签发。
