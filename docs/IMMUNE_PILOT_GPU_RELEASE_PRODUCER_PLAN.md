# 人工 GPU runtime release：最小方案，尚未实现

2026-10-01，只读设计审查及 CPU 修正证据同步。本审查未修改源码或重跑测试；39 个模型文件、staged patch 和 registry 未改，未运行 GPU、队列或读取真实语料。root 已另行修正尚未部署的 Trainer 原型并保留历史字节，结果见本文末尾。依据：[现有 GPU 合同/执行器](/vepfs-mlp2/c20250601/251105016/project/dllm_test/scripts/architecture_prototypes/certified_pilot_execution.py)、[指标 v2](/vepfs-mlp2/c20250601/251105016/project/dllm_test/scripts/architecture_prototypes/validation_metrics.py)、[原构造工厂](/vepfs-mlp2/c20250601/251105016/project/dllm_test/scripts/architecture_prototypes/certified_pilot.py)。

**结论：使用新 producer + 强验证 wrapper，无需复制整个 executor。共享 Trainer 的完整窗口累积修正已通过两环境 CPU oracle；实际 backbone、BF16/AdamW 与训练/四档评估的 GPU 验收仍未完成，当前不能签发 runtime GPU 通过。**

1. **来源与入口。** 与 six 对齐：R20 原任务终态并归档后，完整复制 immutable release 到独立 pilot runtime；39 模型字节不变，支持源码及 pilot/metrics 以归档时最终验收版本为准。修正前版本按独立 manifest 保留原字节和历史报告，不覆写旧验收的 SHA。派生 runtime 不覆盖归档文件，只添加固定新脚本；`runtime_manifest` 绑定 base manifest 和全部文件 SHA。producer 必须独立构造人工 Dataset，复用同一 `make_model`、`training_arguments`、`TokenValidationTrainer` 和 collator；不能调用/绕过真实 `build_trainer` 的 `assert_ready`，也不制作假数据证书。模型 profile 与人工 runtime 合同可独立读取。未来真实 pilot wrapper 首先调用原 preflight 保留数据门禁第一，再强验扩展 GPU 报告，最后调用原 `execute`；原 checkpoint 侧车已经绑定完整 GPU summary/COMPLETE 字节 SHA，额外字段也被覆盖。wrapper 必须验证这些字段，不能只依赖旧 verifier 会忽略的扩展内容。

2. **必须实际执行的训练路径。** 一个固定变体、原 LLaDA 骨干/options/原 micro-mean objective、原 profile 的 microbatch、global=256、GA=256/micro、FP32 参数/AdamW + BF16 autocast、10000 步调度期限不变。真实 `Trainer.train` 的 CPU oracle 已发现并修复 kwargs 签名使 GA 跳过除法的问题：共享 `TokenValidationTrainer.__init__` 明确设 `model_accepts_loss_kwargs=False`，producer 与真实 pilot 使用同一类和来源版本，无需复制 executor 或 monkeypatch。已验收范围仅为完整窗口及 `compute_loss_func=None`，不扩展到尾窗口。仅调用 `compute_loss.backward` 不足；人工 GPU 首窗仍应保留与 manual loss/GA 对照的可复现梯度检查；参考阶段独立于正式峰值测量，避免参考副本污染显存。正式测量建议固定 **3 个完整 optimizer 窗口**，实际计数 microsteps、记录数、optimizer steps、有限/非零梯度、参数更新及 AdamW state；不以三步 loss 降低作学习质量门槛。

3. **必须实际执行的新评估路径。** 使用已有人工 fixtures 的不同分组/长度与独立随机整数 stress 输入，不读取真实语料。必须通过真正的 `trainer.evaluate()` 执行四档 mask；至少两个不等大小的人工 source，覆盖 padding、单/双目标、relation 有/无、空指标 None，并另有实际达到配置最大输入长度和容量的 stress batch。保存每 source×mask 的原始和/计数、完整 v2 指标、source macro、token micro、四 mask 均值和全 mask endpoint 指标；用 CPU 计数 oracle 重算，不仅保存四个 loss。记录实际 tensor 形状/有效槽位和模型设备/dtype，不将 config 抄写当成输入观测。evaluate 前后比较 Python/NumPy/Torch CPU/CUDA RNG 状态，包含 callbacks。

4. **显存和完成证据。** 真实 CUDA 查询记录 GPU 名/UUID/总量、Torch/CUDA/cuDNN/Transformers/Accelerate、训练/评估 autocast、实际类和固定 RNG/输入 hash。训练峰值必须覆盖首次 AdamW state 分配、后续 optimizer step；四 mask 峰值在 optimizer state 仍驻留时测量，包含满长压力输入。同步后 reset/read CUDA peak，保留 allocated/reserved、基线、实际批次和耗时；分别满足旧合同的 ≤85% 总显存，OOM 不缩小输入/批次后沿用原身份。新报告绑定 producer、wrapper、runtime manifest、人工 fixture/plan、原 profile、全来源前后 SHA、原始结果 SHA、正常子进程退出及清理证据。仅真实两阶段和全部检查通过才写 `GPU_RELEASE_COMPLETE`；失败保留分类报告，无通过标记。该证据只验证软件 runtime，不认证数据或生物学效果。

5. **最小运输与 CPU 范围。** 后续单独 release 可新增一个固定 typed variant，例如仅对应 R20 控制款的 `d01_pilot_runtime_gpu_r20_v1`，沿用 `{variant, mode:profile-synthetic, steps:1}`；steps=1 仅表示一次固定计划，不伪造 global_step。原模型 profile/派生 runtime 路径由固定映射解析，无 data/resume/shell 或任意目标参数。建议整个计划上限 1200 秒，分阶段有界、复用已验收的进程组清理；最终预算仍需结合首轮实测审阅。使用独立 kind 和监督分支，不复用 d00 的 `training_started=false`（这里确有人工 optimizer 更新）。CPU 可测字段/哈希/拒绝路径、固定计划、真实 HF 窗口 oracle、聚合和恢复绑定；不能用 mock CUDA 字段签通过。其它架构必须各自测量，不从 R20 自动继承。

**剩余 gap：** ① 完整窗口的 CPU 缩放和共享 factory 接入已闭合，尾窗口、真实 backbone、BF16/AdamW、GPU 与恢复行为尚未由该 oracle 证明；② 现 verifier 只验 CUDA 布尔、loss 个数、trainer 字符串和峰值，必须由新 wrapper 补实际窗口、计数、RNG、producer/runtime 来源及退出证据校验；③ 新 GPU 报告原始 schema、数值 oracle 限界和分阶段时间预算待固定，不能失败后放宽；④ six 的派生 runtime/固定外部资源别名还需独立验收，producer 不读取那些资源；⑤ 当前只读方案未实现 typed 路由或 GPU producer，也没有可用的真实通过材料。
